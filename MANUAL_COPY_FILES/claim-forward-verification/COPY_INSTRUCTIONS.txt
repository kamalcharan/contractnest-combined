Owner: "claim did not work" — buyer tenant, /contracts/claim, CNAK-D73613 +
mobile 9949701175 → "We could not verify this claim…" (VERIFICATION_REQUIRED).

Submodule affected: contractnest-api only. One file. No UI, edge or DB
change. Restart the API after copying.

─── WHAT WAS WRONG ──────────────────────────────────
 CNAK-lite v2 made claim_contract_by_cnak refuse a bare CNAK: the caller
 must send the review link's secret (auto-claim) or the mobile number the
 seller has on file (manual claim). The UI sends them, the edge forwards
 them, contractService.claimContract accepts them — but
 contractController.claimContract read only `cnak` from the body and called
 the service with four arguments, so the RPC always got p_secret NULL and
 p_mobile NULL. Every manual claim through the API has failed since v2;
 the grant for CN-1010 carries the buyer's mobile (+919949701175) and the
 typed number matched it — the RPC never saw it. (The registration-time
 auto-claim calls the RPC directly from the auth edge function and was
 unaffected.)

─── WHAT CHANGED ────────────────────────────────────
 contractnest-api/src/controllers/contractController.ts
 · claimContract reads `secret` and `mobile` from the body (trimmed,
   strings only) and passes them as the service's 5th/6th arguments.
   Nothing else touched.

 Noted, not changed: the service calls the edge with environment 'live'
 hard-coded for claims, so a Test-mode contract can never be claimed
 through this route (the RPC would answer ENVIRONMENT_MISMATCH). Fine for
 the signia → buyer test, which is Live on both sides.

Production checklist
  Transactions: the RPC is one transaction (already).
  Races:        the RPC locks the grant row FOR UPDATE (already).
  Errors:       unchanged — RPC refusals surface as before.
  Toasts / Loaders: UI untouched; existing claim page toasts + VaNiLoader.
