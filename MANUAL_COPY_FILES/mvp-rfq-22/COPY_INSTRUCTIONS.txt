BUG FIXED (real fix this time, not a patch on the last one)
─────────────────────────────────────────────────
User pushed back on mvp-rfq-21's fix after testing an Elevator/Lift
coverage line and seeing the suggestion's description read
"Covers: Hydraulic Oil Temperature" — correctly called this out as wrong:
"KT should generate description right." They were right. mvp-rfq-21's
"Covers: <checkpoint names>" was a client-side stand-in I built because I
hadn't found the real source — it was never meant to be the final answer,
but I should have kept looking before shipping it as the fix.

Went back and searched the KT schema properly this time (not just the
tables I'd already looked at) and found m_kt_service_definitions — a table
that exists SPECIFICALLY for this: one row per "sellable service"
(resource_template_id + service_name + description), explicitly commented
in the edge function as a founder decision ("description stored ONCE —
m_kt_service_definitions, not repeated on checkpoints"). It's already
queried and returned by GET /knowledge-tree/summary
(`service_definitions: serviceDefs || []`) — I just never noticed because
the frontend KnowledgeTreeSummary TypeScript type didn't declare that
field, even though the edge function has always returned it.

Verified live: for Elevator/Lift's "Hydraulic System Check"
(checkpoint "Hydraulic Oil Temperature", resource_template_id
598f5591-...), m_kt_service_definitions has a real authored paragraph:
"Covers monitoring of hydraulic oil temperature and fluid level to ensure
the system operates within designed parameters. Low oil or overheating
leads to sluggish performance, seal damage, or sudden shutdown. Essential
for hydraulic elevator reliability and long-term cylinder and pump
health." That is what should have shown up, and now does.
