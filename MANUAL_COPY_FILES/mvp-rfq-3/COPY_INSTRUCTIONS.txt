WHAT THIS FIXES
───────────────
  You asked: "there is no way to see where my RFPs are — contracts hub only
  focuses on contracts, not RFP."

  It was worse than hidden. The hub never passed record_type at all, so your
  RFQ (contract_type 'vendor') actually LEAKED into the Expense vendor-contract
  list — but with status 'sent', which the contract status pills don't model,
  so it showed up mis-bucketed with wrong pipeline maths and no "this is a
  request" marker.

  Now:
    * Expense mode gets a "Contracts | Requests" toggle.
    * "Requests" filters to record_type = 'rfq' and swaps the pipeline pills to
      the RFQ lifecycle: Draft · Sent · Quotes In · Awarded · Converted.
    * "Contracts" now explicitly filters record_type = 'contract' — which also
      stops RFQs leaking into the contract list. That leak is fixed for free.
    * Revenue mode is untouched — an RFQ is an expense-side concept (a buyer
      asking vendors to quote), so the toggle only appears in Expense.


HOW IT REUSES WHAT EXISTS  (your question — "how will you use existing code")
────────────────────────────────────────────────────────────────────────────
  * useContracts already accepts record_type — the hook needed NO change.
  * get_contracts_list RPC already filters on p_record_type — DB needed NO
    change.
  * CONTRACT_STATUS_COLORS already carries sent/quotes_received/awarded/
    converted_to_contract labels + colours — the row badge renders RFQ statuses
    correctly with no new map.
  * ContractPortfolioRow already renders every RFQ needs — one line changed so
    it shows rfq_number instead of a blank contract_number for requests.
  * The RFQ pipeline counts read from the SAME stats payload: every RFQ status
    is RFQ-exclusive (a contract is never 'sent'/'quotes_received'/'awarded'),
    so the counts are accurate even though the stats endpoint scopes by
    contract_type, not record_type. No new stats call.

  Net new code: a toggle, a second pipeline-stages array, and a one-line row
  tweak. Everything else is wiring that already existed.
