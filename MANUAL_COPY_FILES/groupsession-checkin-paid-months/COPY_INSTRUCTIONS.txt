THE BUG
-------
Line 479 read:

    amount: e.remaining ?? e.amount,

`remaining` is produced by the RPC gs_member_history as:

    greatest(0, coalesce(e.amount,0) - coalesce(e.amount_settled,0))

For any settled instalment that is 0 BY DEFINITION. So every paid month
rendered as "₹0" — while the TOTAL PAID tile immediately above it showed
the real figure. A member who had paid Apr-Jul saw four ₹0 cells and
reasonably concluded their payments were never recorded.

The `??` fallback was also dead code: the RPC never returns null for this
field, and `0 ?? x` evaluates to `0`, so the fallback could never fire.


THE FIX
-------
    amount: e.amount,

This is the same field the Dues grid already renders
(contractnest-ui/src/pages/operations/group-sessions/index.tsx:1039 ->
`money(c.amount, r.currency)`), fed by gs_dues_matrix which emits
'amount' as sum(amt) and keeps settlement separately as 'paid'.
Check-in now reads the same number the chair reads.

`state` already carries paid-vs-due, so the colour communicates
settlement; the number does not need to double as a balance.

Deliberately NOT changed: the CURRENT due card (line ~1454) and
arrearsTotal (line ~465) still use `remaining ?? amount`. That is
correct for those two — for an unpaid or part-paid instalment you do
want what is still owed.
