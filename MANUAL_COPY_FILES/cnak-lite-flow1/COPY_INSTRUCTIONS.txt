WHAT THIS PHASE DOES
--------------------
1. SECURE CLAIM (migration 010): claim_contract_by_cnak v2.
   - Bare-CNAK claiming is REJECTED (code VERIFICATION_REQUIRED).
   - AUTO-CLAIM  : CNAK + secret_code (from the review link).
   - MANUAL CLAIM: CNAK + registered mobile (last-10-digit match against
     the access grant's contact channels).
   - p_is_live NULL = adopt the contract's environment (used by the
     server-side signup auto-claim). Explicit true/false keeps today's
     strict environment check.
   - Old 4-arg signature DROPPED first (avoids PostgREST overload trap).
   - Forward-only, no backfill.

2. LITE-BUYER SIGNUP: review page → /register?ref=CNAK already existed
   but the CNAK died at the API. Now it flows end-to-end:
   RegisterPage recovers the review-link secret from the stored redirect
   → AuthContext sends cnakRef+cnakSecret → API forwards → edge register
   marks t_tenant_onboarding.onboarding_type='cnak' (is_completed stays
   false — that incompleteness IS the lite tier flag) and AUTO-CLAIMS the
   contract (non-fatal: signup never fails because a claim did; response
   carries cnak_claim result).

3. TIER VISIBILITY: GET /api/onboarding/status now returns
   onboarding_type (top-level + inside data) so Phase B can derive the
   lite tier in the UI.

4. CLAIM PAGE kept working under v2: /contracts/claim now has a
   "Registered Mobile Number" field (hidden if ?secret= is in the URL)
   and sends secret/mobile with the claim.
