WHAT WAS NOT DEAD (the finding that shaped this)
───────────────────────────────────────────────────────────────────
E was scoped as "delete dead code". Three surfaces turned out to be
LIVE and still writing through the Firebase client SDK, which is what
was actually blocking the storage.rules deploy:

  catalog-studio/blocks/new.tsx + [id]/edit.tsx
      Block image upload. MIGRATED to the broker
      (useUploadIdentityAsset('block_icon')). The
      "Storage is not configured, please set up storage in Settings"
      guard is gone with it - there is no folder to provision.

  BlockWizard MediaStep
      Block VIDEO upload, via components/common/FileUploader.
      REMOVED rather than migrated: the broker's MIME allowlist has no
      video types, and t_tenant_files shows ZERO block_videos have
      ever been uploaded. Building unmetered video support for a
      feature nobody has used was the wrong trade. YouTube, Vimeo and
      a direct URL all still work; only the "Upload" source type went.

  VaniWorkingStep  ← the important one
      Still called POST /api/storage/setup on EVERY new tenant, so
      every signup was still being given a legacy per-tenant folder.
      This is POA point 2, and it would have kept recreating exactly
      the mess the storage admin screen exists to clean up.
