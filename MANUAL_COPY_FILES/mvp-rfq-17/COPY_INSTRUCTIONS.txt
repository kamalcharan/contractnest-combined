BACKGROUND — the gap analysis (Spare Part: catalog-studio vs FlyBy)
────────────────────────────────────────────────────────────
Checked catalog-studio's Spare Part definition (BasicInfoStep/InventoryStep/
FulfillmentStep) against the FlyBy card. Inventory/Fulfillment fields (stock,
warehouse, lead time, shipping) are catalog/master-data only — confirmed they
appear NOWHERE in the per-contract block editor (BlockCardConfigurable), so
correctly out of scope for a FlyBy line. SKU was flagged as a possible gap but
owner decided AGAINST adding it — a loose FlyBy/RFQ line asks by CATEGORY +
quantity, not a tracked SKU. This batch adds exactly that.

────────────────────────────────────────────────────────────
WHAT CHANGED
────────────────────────────────────────────────────────────
Spare Part FlyBy lines (Contract AND RFQ, both use this same card) now have a
Category selector — the SAME 4 options catalog-studio's Basic Info step offers
when an admin defines a spare part block: Filters / Gases / Parts / Accessories
(ids: filter/gas/parts/accessories — matched exactly so a value written here
reads identically to the catalog side). Placed right after Visits/Price, chip-
style like Billing Cycle. Also shown as a chip in the collapsed summary line.
No SKU field — deliberately not added.
Persists to custom_fields.config.spareCategory.

────────────────────────────────────────────────────────────
VERIFIED — real transaction, not just code review
────────────────────────────────────────────────────────────
Ran create_contract_transaction live (setup tenant) with a spare block
(quantity=5, config.spareCategory='filter'), then read it back via
get_contract_by_id (the same RPC the UI calls). Confirmed exact round trip:
  "quantity":5, "custom_fields":{"config":{"flyby_type":"spare","spareCategory":"filter"}}
Test row deleted immediately after — zero residue left in the tenant's data.
