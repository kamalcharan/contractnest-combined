WHAT THIS ADDS
─────────────────────────────────────────────────
Two things requested on top of the KT recommender:
  1. Spare parts alongside services in the suggestion sidebar.
  2. A type tag (Service / Spare Part) on every suggestion card, so it's
     obvious at a glance which kind you're looking at.

Deliberately NOT attempted: variant-aware filtering. KT models multiple
equipment variants per resource template (e.g. DG Set has 10, by capacity
range — "DG Set — Portable/Inverter 1-10kVA" through "DG Set — High-
Capacity Industrial 500-2500kVA"), and some checkpoints/spare parts are
variant-specific (CheckpointVariantMap / SparePartVariantMap). Checked
whether the tenant's own registry records which variant a resource
actually is — it doesn't: t_category_resources_master (the table behind
/api/resources) has no variant_id or anything like it. So there is no
reliable signal to filter suggestions by variant even if we wanted to.
This batch shows every service/spare for the matched resource_template_id,
unfiltered — flagged in-code as a known limitation, not silently ignored.
Whether/how to add variant capture to the registry is a separate,
bigger decision for later.

Files Changed:
  - contractnest-ui/src/components/catalog-studio/BlockCardConfigurable.tsx
      Added config.ktSparePartId (parallel to config.ktCycleId, but for
      spares — no cadence, so no cycle id to key off) and config.ktPriceUnit
      (spare parts are priced "per unit" / "per set", not a flat figure,
      so the unit travels with the price range for reference display).
  - contractnest-ui/src/pages/contracts/rfq/RfqBuilderPage.tsx
      - KTSuggestionsForCoverage now builds spareSuggestions from
        summary.spare_parts_by_group (already returned by the same KT
        summary call, no new backend read) alongside the existing service
        suggestions, and merges them into one list, services first then
        spares (matches the Contract wizard's own section ordering).
      - Every suggestion card now shows a small colored tag (Service /
        Spare Part), reusing FLYBY_TYPE_CONFIG's existing colors so it's
        visually consistent with the FlyBy add-menu elsewhere.
      - addFromKT() now takes the discriminated KTSuggestion (kind:
        'service' | 'spare') and creates the right FlyBy block type. Spare
        part suggestions map KT's component_group onto the RFQ's 4 fixed
        spare categories (Filters/Gases/Parts/Accessories) — only
        "filters" has a clean match; controls/electrical/mechanical/
        safety/water_side all default to "Parts", which is approximate
        but honest rather than guessing a wrong specific bucket.
      - addedKtIds (renamed from addedKtCycleIds) now dedupes against
        BOTH config.ktCycleId and config.ktSparePartId, so an added spare
        suggestion also stops re-showing.

Submodules Affected: contractnest-ui only. No DB/API change — spare parts
were already part of the same GET /knowledge-tree/summary response used
since mvp-rfq-20, just not read until now.
