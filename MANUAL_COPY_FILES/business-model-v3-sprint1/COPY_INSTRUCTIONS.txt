═══════════════════════════════════════════════════
NOT INCLUDED — deliberately
═══════════════════════════════════════════════════

t_bm_credit_lot (FIFO lots) is NOT created.

Owner decision 2026-08-05: credits never expire — they are consumed and
have no end date. Baseline §5 D6 confirms nothing has ever written
expires_at (purchase_topup computes an expiry and then discards it,
because add_credits has no expiry parameter; every expires_at in the
database is NULL).

Lots exist only to make expiry correct, so they are deferred until
Mode A (the 1-year wallet) ships.

  => When Step 5 cleans up the duplicate topup packs, set
     expiry_days = NULL on every surviving pack, so the expiry-wipe
     defect (spec §5.1) stays unreachable.
