WHAT NEEDS COPYING — UI ONLY
═══════════════════════════════════════════════════

Files:
  contractnest-ui/src/types/catalogStudio.ts              [MODIFIED]
  contractnest-ui/src/utils/catalog-studio/categories.ts  [MODIFIED]
  contractnest-ui/src/hooks/queries/useBlockTypes.ts      [MODIFIED]

Purpose: gate the new "Credit Pack" (metering) block type to the platform
tenant only.

WHY A UI GATE AND NOT A DATABASE ONE:
  m_category_details has NO tenant_id — block types are platform-wide.
  There is no way to scope this type to one tenant in the database, so the
  filter has to live in useBlockCategories(), keyed on
  currentTenant.is_admin.

The three changes:
  1. types/catalogStudio.ts
       BlockCategory gains `adminOnly?: boolean`, alongside the existing
       comingSoon / singleton MVP gates.
  2. utils/catalog-studio/categories.ts
       'metering' added to BLOCK_CATEGORIES (fallback) and to
       MVP_CATEGORY_OVERRIDES as { adminOnly: true }.
  3. hooks/queries/useBlockTypes.ts
       useBlockCategories() now reads currentTenant and filters out
       adminOnly types for non-admin tenants.

No existing behaviour changes for any other block type.

STEP 4: Activate the block type (ONLY after UI is deployed)
═══════════════════════════════════════════════════
The metering type is seeded is_active = FALSE so it is invisible to
everyone until the gate above ships. Once it is deployed:

UPDATE m_category_details SET is_active = true
 WHERE sub_cat_name = 'metering'
   AND category_id = (SELECT id FROM m_category_master
                       WHERE category_name = 'cat_block_type');

If you activate it BEFORE deploying the UI, every tenant sees a
"Credit Pack" card in catalog-studio.
