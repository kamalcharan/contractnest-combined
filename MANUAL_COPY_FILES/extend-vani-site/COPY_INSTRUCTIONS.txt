WHAT IT IS
  · one script tag  <script src=…/embed.js data-vani="vn-…" async>  puts a
    floating VaNi bubble on every page of the tenant's own website; the panel
    is /vani-chat/:key in an iframe. data-view="bubble" on a storefront tag
    does the same scoped to that storefront. ContractNest.vani(key) for devs.
  · "Ask VaNi" on the package page (/p/:key) and on the widget card when the
    tenant's VaNi is on — the same VaniChat component.
  · she answers ONLY from the published packages + the storefront FAQs:
    FAQ first (token overlap, no model), then the VaNi LLM (vaniLLMClient,
    structured JSON, grounded prompt), else a deterministic hand-off. Every
    answer may carry one package card (Buy → checkout, Explore → page).
  · a name + mobile in the chat → lead_capture kind 'vani' (migration 039):
    shows on /leads as "asked VaNi" with the question; the tenant gets an
    email through n_jtd (template lead_captured_email — provider id NULL
    until registered, so it is skipped for now, like contract_accepted).
  · Extend page → "VaNi on your site": greeting · when she can't answer
    (take number / open WhatsApp) · ask for name+mobile (interest / first /
    never) · allowed sites · snippet · live preview (the real chat) · month
    and all-time counters. Ghosted counterfactual when VaNi is off.
  · gated on vani_is_enabled(): chat and lead endpoints answer VANI_OFF (403);
    the storefronts and checkout keep working without VaNi.
