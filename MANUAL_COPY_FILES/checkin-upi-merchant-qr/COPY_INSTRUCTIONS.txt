BATCH: checkin-upi-merchant-qr (2026-09-16)
═══════════════════════════════════════════════════
Owner request: resolve the long-open "check-in UPI pay link fails on real
GPay" item (CLAUDE.md, raised 2026-07-25) — the mc=0000 fix from that
session didn't work. Owner scanned the physical Karnataka Bank QR sticker
for U S R Travels with a plain QR reader and shared the raw decoded
payload, which cracked it.

Submodules affected: contractnest-ui, contractnest-edge (DB — see below).

─── ROOT CAUSE ──────────────────────────────────────

The hand-built upi:// intent declared the transaction as PERSONAL (P2P)
while the receiving VPA (9849502193@kbl) is actually registered on the
UPI network as a MERCHANT account. Decoded real QR:

  upi://pay?ver=01&orgid=159052&mode=01&pa=9849502193@kbl&pn=U%20S%20R%20TRAVELS&mc=4722&cu=INR

vs. what our code built (after the earlier mc=0000 attempt):

  upi://pay?pa=...&pn=...&tr=...&tn=...&am=...&cu=INR   (no mc at all — a
  later session had removed mc=0000 rather than fix it, per its own code
  comment "do not fabricate merchant category... not supplied by a PSP")

THREE fields were missing entirely: ver, orgid, mode. And the merchant
category code was wrong in the opposite direction from the earlier fix
attempt — mc=0000 means "not a merchant" (personal transfer); the real
value is 4722 (Travel Agencies and Tour Operators, the correct ISO 18245
code for "U S R Travels"). Declaring the wrong transaction type against a
merchant-registered VPA is exactly the kind of mismatch that produces
"Payments to this receiver are not allowed by UPI network".

Per-tenant/per-environment scoping matters here: BBB also has a TEST-
environment offline_upi config using a personal VPA
(kamalcharan@okicici) — genuinely P2P, correctly has neither org_id nor
mcc, and must keep building a plain intent with none of these fields.
This is why org_id/mcc live in the tenant's own config (JSONB, no schema
change) rather than being hardcoded anywhere in the app.

PART 2 (added same day): self-service for ALL tenants, not just BBB
═══════════════════════════════════════════════════
Owner question after Part 1: "will it work for all tenants?" — no. Part 1
was a one-off manual database patch for BBB's specific org_id/mcc values.
Investigated /settings/integrations ("we have a placeholder... needs to
be tackled from there") and found it's a fully schema-driven settings
page — Offline UPI's form fields (upi_id, payee_name, qr_image_url) come
from a config_schema on the provider row, not hardcoded React. The
qr_image_url field already lets a tenant upload their bank's QR — it was
just never decoded, only ever displayed as a picture.

Part 2 makes that upload do double duty: decode the QR server-side the
moment it's uploaded, and if it's a genuine UPI merchant QR, silently
extract org_id/mcc and carry them into the same credentials the tenant is
already saving — without ever asking what a "merchant category code" is,
and without adding a single new visible field to the form.

─── ROOT CAUSE OF A SECOND BUG FOUND ALONG THE WAY ───
While tracing exactly how a saved value could later be lost, found that
the edge function's save path did a FULL REPLACE of the credentials
JSON on every save (`credentialsJsonb.public = requestData.credentials`),
confirmed at the SQL layer too (save_tenant_integration does a hard
`credentials = p_credentials::jsonb`, no merge). Since org_id/mcc are
deliberately UNDECLARED fields (never loaded into the edit form's state),
any later edit to something else entirely (e.g. just changing the payee
name) would have silently wiped them the very next time the tenant saved
anything. Fixed by making the edge function fetch and merge the existing
public credentials before writing, instead of replacing them outright —
scoped narrowly to the plaintext `public` blob only (non-secret display
values); the separate `encrypted` blob (API keys for Razorpay/Stripe/etc.)
was deliberately left untouched — that's a bigger, unrelated risk
surface flagged separately, not fixed here.

 9. contractnest-ui/src/components/integrations/IntegrationSetupModal.tsx
