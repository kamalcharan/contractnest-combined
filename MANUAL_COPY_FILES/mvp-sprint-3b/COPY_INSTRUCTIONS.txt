WHAT WAS REPORTED
─────────────────
  The pricing step shows one button, "Accept KT pricing", and reads as though
  the tenant has no choice but to accept.


WHAT IS ACTUALLY THERE — the options existed, they were just quiet
──────────────────────────────────────────────────────────────────
  Reading Screen8APricingStep before changing it:

    line 352   every row has an `edit` control that opens an inline price field
    line 343   with save / cancel
    line 521   unpriced groups get a "Fill unpriced" action
    line 397   a Skip in the empty state
    line 552   "Skip for now — I'll set prices later" under the list
    line 652   the primary button is ALREADY dynamic:
                 changed > 0  ->  `Confirm pricing (N edits) →`
                 changed = 0  ->  `Accept KT pricing →`

  So a tenant can edit every price, fill gaps, or skip entirely. The button
  only says "Accept" because they have not edited anything yet — technically
  accurate, and it reads like an ultimatum.

  Three real problems, none of them a missing feature:

    1. "KT" is internal vocabulary. A tenant on day one has never heard of a
       Knowledge Tree and cannot know whether accepting it is safe.
    2. The `edit` control is a small text link on each row, easy to miss when
       the eye goes straight to the big button at the bottom.
    3. Nothing on the screen says where the numbers came from, so "accept"
       sounds like agreeing to something binding.


WHAT CHANGED
────────────
  1. AN EXPLAINER CARD, first thing in the right panel

     The panel is already a 1fr/300px grid (line 434) carrying a Pricing
     Progress card and a Catalog Summary card. A third card goes ABOVE both,
     so it is read before the numbers:

       "Where these prices come from
        These are market-reference prices we researched for your equipment —
        a starting point, not a quote.
        Change any of them now with the edit link on each row, or leave them
        and adjust later — every price stays editable in Catalog Studio.
        Nothing is sent to a customer from this screen."

     It names the `edit` control explicitly, which is what makes the row
     affordance findable, and it names Catalog Studio — which is reachable
     again since Sprint 2f unwired that nav gate.

  2. THE BUTTON

       'Accept KT pricing →'   ->   'Use these prices →'

     The edited-state label is unchanged: `Confirm pricing (N edits) →`.
     "Use these" is a choice; "Accept KT" is a demand in a language the tenant
     does not speak.

  3. THE PROGRESS TABLE

       'KT suggested'  ->  'Suggested'

     Same number, no jargon.

  4. "BEGIN YOUR SETUP JOURNEY" — the header subtitle

     Every express screen showed that same line, on every step, as if the flow
     never moved. Same root cause as the header title fixed in Sprint 2c:
     OnboardingUtils.getStepDefinition has no entry for these routes, so
     currentStepDef is undefined and the header falls back to a generic string.

     JourneyStep now carries an optional `blurb`, and the header uses it on the
     express journey:

       Your business      Name and what you do
       What you service   Pick your equipment — we work out the rest
       Building           Building your catalog
       Your prices        Market-reference prices — edit any of them, or
                          change them later
       Your terms         The terms your contracts carry
       Your assets        What you own and maintain
       Your lists         Roles and tags for your team
       Workspace ready    Everything is set up
       First contract     A rehearsal, in test mode
       Your plan          Nothing is charged today

     Off the express journey the old fallback is untouched.
