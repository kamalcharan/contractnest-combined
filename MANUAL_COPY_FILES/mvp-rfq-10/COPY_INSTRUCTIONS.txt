WHAT CHANGED
The "Scope" step (was "Services") no longer offers a single generic "service
line". It now uses the real FLYBY controls — the same four block types as the
contract wizard (from the shared FLYBY_TYPE_CONFIG):
  • Service   — with a cadence (Monthly … One-time)
  • Spare Part — with a quantity
  • Text       — a free-text note the vendor should read/agree to
  • Document   — an expected file type (PDF/DOCX/…)
FlyBy = structure only. NO library, NO pricing — the buyer names each block now;
the vendor fills the price when quoting. Each block maps to the existing payload
`blocks[]` with source_type:'flyby', flyby_type, block_name, quantity, and (for
service) billing_cycle; type-specifics (content, fileType) ride in custom_fields.
Review step shows each block with its type badge.
