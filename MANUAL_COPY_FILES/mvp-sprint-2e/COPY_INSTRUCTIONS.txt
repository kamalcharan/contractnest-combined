THE MISSING HALF: RevealSignalsBridge
─────────────────────────────────────
  RevealProvider deliberately does not fetch. That is fine for a screen that
  already holds its numbers, and useless for the sidebar, which renders on
  every page and needs the answer before anything else has loaded. Without a
  source, every signal stays undefined forever and the module is inert — which
  is exactly the state it was in.

  RevealSignalsBridge renders nothing and pushes three signals, using the SAME
  hooks the app already uses so React Query dedupes rather than duplicates:

    useContractStats()   -> contractCount AND vendorContractCount
                            (one call: the response already carries
                             by_contract_type, contracts.ts:616, so the
                             expense-side count comes out of the same payload)
                            Sidebar.tsx already calls this hook, so on most
                            pages it is a cache read, not a request.
    useGroupSessions()   -> usesGroupSessions

  TWO cached reads per session, not per page. The original design note claimed
  "adds no queries"; that was not survivable, and pretending otherwise would
  have meant shipping a module that never hides anything. This is the honest
  price.

  Every push is guarded on the query having SUCCEEDED. While loading or errored
  the signal stays undefined -> fails open -> the surface shows. A slow or
  broken API can never blank out a tenant's navigation; it can only fail to
  hide something.
