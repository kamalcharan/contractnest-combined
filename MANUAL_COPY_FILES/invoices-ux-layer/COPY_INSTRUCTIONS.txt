WHAT THIS IS
------------
The Invoices section as a first-class NAV area, product-led design per the
Finance-Metered-V3 direction, translated into the app's own theme tokens
(light + dark). Three pages:

  /invoices          Hub — clickable totals strip (Outstanding / Overdue /
                     Collected·Drafts), filter chips (All/Open/Overdue/
                     Ad-hoc/Drafts), search, rows with a human reason line
                     ("₹6,000 received · ₹13,500 open · 12d late").
  /invoices/new      Composer — replaces the AdHocInvoiceDialog experience:
                     app chrome outside, branded document inside (accent
                     bar, logo block, INVOICE title, meta, Bill To strip),
                     inline typeahead add-line grouped by catalog category
                     + Browse-catalog accordion modal, editable rate/qty/
                     tax, Bill To picker in the right sidecard, "money
                     already received" payment block with receipt promise
                     in plain language.
  /invoices/:id      Viewer — same document chrome read-only, receipts
                     section with the green "Receipts — unlimited · free"
                     badge, Record payment button (stub), works for
                     contract-linked AND ad-hoc invoices (closes the
                     "ad-hoc invoice has no page" gap).

PLG layer per the settled model:
  - "Invoicing — included · unlimited" badge (no metering anywhere).
  - Entitlement gate stub: canCreateAdhocInvoice in sampleData.ts. Set it
    to false to preview the locked composer + "See plans" upsell state.

PERSPECTIVE RULE (as agreed this session):
  - NAV item "Invoices" renders ONLY in Revenue perspective. An invoice is
    a seller's instrument.
  - In Expense perspective the /invoices route stays reachable (for cross
    links) and renders a pointer card to Finance (AR/AP) and Subscription
    instead of the seller workspace.


⚠ UX SAMPLE MODE
----------------
ALL data on these pages comes from src/pages/invoices/sampleData.ts —
sample rows shaped exactly like live t_invoices reality (BBB amounts, two
guest-fee ad-hoc cases, partial payments). Save/Record-payment actions
show a toast instead of writing. This is deliberate: judge the UX freely,
nothing can touch production. Batch 2 (wiring) replaces sampleData.ts with
GET /api/invoices + GET /api/invoices/:id (new API pair), connects the
composer to the existing create_adhoc_invoice flow, re-points the
group-sessions / contacts entry buttons, and swaps the entitlement stub
for the tenant-context flag.

To preview the declaration hand-off flow now: /invoices/new?prefill=guest
(pre-fills Tejaswinni's ₹600 guest fee + UPI reference, payment ON).
