2. admin_purge_orphan_auth_users(p_dry_run boolean DEFAULT true)
   New. The "orphan" option. Closing an account clears its tenant data but
   leaves the auth identity behind (143 auth.users against 77 tenant links).

   A user is an orphan only if ALL of these hold:
     - no t_user_tenants row
     - no t_user_profiles row
     - not referenced by t_contacts.auth_user_id, t_audit_logs.user_id,
       t_tenant_files.created_by, t_invitation_audit_log.performed_by,
       or any of the five t_user_invitations actor columns
     - every tenant they created is already empty of members

   t_tenants.created_by is NO ACTION and nullable, so it is set to NULL
   rather than cascading the tenant row away -- the tenant record survives,
   it just loses its creator pointer.

   Defaults to a DRY RUN. service_role only (revoked from anon/authenticated).

   Usage:
     select admin_purge_orphan_auth_users();       -- dry run, lists them
     select admin_purge_orphan_auth_users(false);  -- actually delete
