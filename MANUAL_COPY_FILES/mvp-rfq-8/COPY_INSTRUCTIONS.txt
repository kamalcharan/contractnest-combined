WHAT CHANGED
────────────────────────────────────────────────────────────
Opening an RFQ used to reuse the CONTRACT detail layout. Now, when
record_type === 'rfq', the detail page early-returns a purpose-built RFQ
report (RfqReport.tsx):
  • Header: request number, CNAK, status pill, and — for the seller — the
    valid status actions (Send / Award / Cancel …) driven by the same
    handleStatusChange the page already uses.
  • Hero: title, nomenclature, term, quote currency, CNAK.
  • Timeline strip: Starts · Term · Last date to apply (with a live
    "N days left / closed" countdown, red once past).
  • What it covers: equipment_details / coverage_types (name, qty, flavour).
  • Services to quote: the flyby service lines with their cadence.
  • Vendors & quotes (the heart): per-vendor status (Awaiting / Quoted /
    Declined / Accepted), quoted amount in the RFQ currency, notes, and a
    quoted/awaiting/declined tally.

NO new route — it renders inside the existing /contracts/:id, so the CNAK/link
a buyer already holds keeps working. Reads only data the detail page already
loads (ContractDetail); no API/edge/migration change.

WIRE-UP in index.tsx (only 2 edits):
  • import RfqReport from './RfqReport';
  • after the loading/error guards:  if (isRfq) return <RfqReport … />;
    (placed after all hooks — safe re: rules-of-hooks)
