What it does, in one transaction:
  §1 PATCHES get_tenant_data_summary — its t_catalog_items and
     t_catalog_categories counts were NOT exception-guarded and WOULD THROW
     once the tables are dropped. (admin_reset_all_data needs no patch: all
     its catalog DELETEs are already wrapped in EXCEPTION WHEN OTHERS.)
  §2 DROPS 20 legacy-catalog-only RPCs
  §3 SAFETY GATE — aborts the whole migration if ANY of the 6 tables has
     gained even one row since this was written
  §4 DROPS the 6 tables:
       t_catalog_items, t_catalog_categories, t_catalog_resources,
       t_catalog_service_resources, t_catalog_resource_pricing,
       t_catalog_industries
  §5 POST-CHECK — raises (rolling everything back) if any table or function
     reference survives

Transactional and fails closed: if anything is unexpected, nothing drops.

Apply via the Supabase SQL editor, or:
