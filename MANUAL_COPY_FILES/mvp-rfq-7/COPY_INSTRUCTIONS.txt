A) RfqBuilderPage.tsx — builder polish (tracker items B4/B3/B6/B2)
   • B4 Currency — was silently hard-coded 'INR'. Now a real "Quote currency"
     selector in the Timing step (INR/USD/EUR/GBP/AED/SGD), wired into the
     payload (`currency`) and shown on the Review summary.
   • B3 Deadline — "Last date to apply" was buried + shipped null (PRJ-1004).
     Now PRE-FILLED to 7 days out (editable), promoted to a prominent
     calendar-icon field, and still flows to `response_deadline`.
   • B6 Nomenclature — was an easy-to-miss optional chip inside "Request".
     Promoted to its own dedicated step ("What kind of contract is this?"),
     placed right after "What for", and REQUIRED to advance (no more null
     nomenclature). Removed the old chip block from the basics step.

     lines the buyer defines (the flyby concept); payload was already flyby.

B) equipment-registry/index.tsx — Expenditure = "my items"
   Model locked with owner: Expenditure→Buyer→MY items (ownership 'self'),
   Revenue→Seller→customer items (ownership 'client', client name captured).
   • The sidebar/grouping now ALWAYS reflects the tenant's OWN configured
     resources (t_category_resources_master via useResources) for BOTH
     perspectives — Expense no longer dumps the full master catalog.
   • The master templates are now used ONLY as the "+ Add" picker (a buyer can
     still add a brand-new owned item type from the full catalog).

     template id OR seeded template_id — so onboarding-seeded instances (which
     carry template_id, not asset_type_id) group and filter correctly instead
