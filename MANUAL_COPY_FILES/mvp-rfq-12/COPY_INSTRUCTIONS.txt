WHAT CHANGED — aligned the FlyBy "Service" block with the real service-block model
Previously the RFQ invented its own cadence chips (Monthly/Quarterly/Half-yearly/
Annual/On call/One-time). That mixed up two different things. Now it uses the
SAME model as the service blocks:
  • BILLING CYCLE — the proper cards: PrePaid · PostPaid · Monthly · Fortnightly ·
    Quarterly · Custom (mirrors the canonical CYCLE_OPTIONS, with icons). This is
    what `billing_cycle` carries.
  • SERVICE CYCLE (frequency) — "Performed every N days from start" numeric input
    (default 30). Frequency is managed here, NOT by the billing label. Persists in
    custom_fields.config.serviceCycles.days.
  • DESCRIPTION — an optional description on every block (service/spare/document;
    text already has its content). Persists to block_description (+ config.notes).
Still no pricing (no visits/price) — the vendor fills price when quoting.
