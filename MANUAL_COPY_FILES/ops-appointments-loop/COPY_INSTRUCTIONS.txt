Production checklist
  Transactions: every tool/RPC is one PL/pgSQL transaction; downstream
                refusals RAISE 'TOOL:…' and roll back (probe: decline →
                re-open → accept left exactly 1 active appointment).
  Races:        FOR UPDATE on the event (ask) and the appointment (respond);
                update_appointment stays version-checked; one action in
                flight per card; single-use-safe (asking twice records
                twice, answering twice is idempotent on accept).
  Errors:       machine-readable reasons → HTTP → REASON_COPY toasts; the
                public page renders the API's message inline.
  Toasts:       react-hot-toast via useToolMutation (board); inline on the
                public page (no Toaster outside the shell).
  Loaders:      board bar + dim (new), per-card spinner, public page spinner.
