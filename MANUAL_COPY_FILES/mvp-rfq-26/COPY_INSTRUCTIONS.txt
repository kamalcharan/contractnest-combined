BUG FIXED: "Failed to submit quote"
─────────────────────────────────────────────────
Reported after mvp-rfq-24/25 wired the vendor route end-to-end: submitting
a quote on the vendor page always failed with the generic
"Failed to submit quote" message.

Reproduced directly by calling rfq_submit_quote against the live PRJ-1005
RFQ. Two CHECK constraints, back to back, both predating rfq_submit_quote
(added in migration 072) and never updated to match it:

  1. t_contract_history_action_check didn't allow the action values
     rfq_submit_quote actually inserts: 'rfq_quoted' (on a quote) and
     'rfq_declined' (on a decline). Error: 23514 on that constraint.
  2. After fixing (1), the SAME insert still failed —
     t_contract_history_performed_by_type_check only allowed
     'user' / 'system' / 'vani', but a vendor answering an RFQ is a
     contact, not a tenant user, so rfq_submit_quote stamps
     performed_by_type = 'vendor'. Error: 23514 on that constraint too.

Same "extend it, don't drop it" pattern as 075_flyby_type_add_session.sql
earlier this session — both guardrails are real and stay in place, they
were just missing values for a feature (RFQ vendor responses) that was
built after they were written.

Verified live end-to-end: called rfq_submit_quote directly, confirmed it
now returns success (response_status: 'quoted'), then reverted every
change the test call made — t_contract_vendors, t_contract_access,
t_contracts.status, and the two t_contract_history rows it created — so
PRJ-1005 was left exactly as you'll find it, ready for you to submit a
real quote through the actual vendor page.
