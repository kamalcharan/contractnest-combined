WHAT CHANGED IN THE PLAN, AND WHY
─────────────────────────────────
  Sprint 2 was written as "build persona -> industry -> furnished workspace".
  It turned out that ALL of it already exists: the VaNi onboarding has 25 step
  components and TOTAL_STEPS = 11. Tracing each step's forward navigation gives
  the real chain, ~16 screens:

    vani-intro -> user-profile -> business-details -> persona-selection ->
    engagement-model -> theme-selection -> industry-selection -> resource-pick ->
    vani-consent -> vani-intelligence -> vani-working -> pricing-review ->
    terms-conditions -> equipment -> lov-setup -> done

  So Sprint 2 became CUT THE PATH, not build it.

  Per your decision (keep pricing-review + equipment + terms; express path
  BESIDE the existing flow), express replaces the first NINE screens with TWO,
  then hands off into the existing chain at vani-working — which already seeds
  the catalog and carries the tenant through pricing -> terms -> equipment ->
  lov-setup -> done, completely untouched.

    /start        business name + persona          (replaces 4 screens)
    /start/trade  served industries                (replaces 5 screens)
    -> /onboarding/vani-working  (existing, unmodified, and everything after it)

  Net: ~16 screens -> ~7. Nothing in the existing flow is edited, and it stays
  fully reachable at /onboarding for anyone who wants the long form (there is a
  link to it on the first express screen).

ROUTING GAP FOUND AND FIXED (added after the first pass)
────────────────────────────────────────────────────────
  /start was unreachable. Tracing the real new-user journey:

    RegisterPage -> tenant creation -> CreateTenantPage -> /ops/cockpit

  A brand-new signup NEVER touched onboarding at all. /onboarding was only
  reached by logging out and logging back in (LoginPage). So the express path
  existed but nothing routed to it.

  Three redirects now point at /start:
    src/pages/auth/CreateTenantPage.tsx  /ops/cockpit -> /start   <-- the one
                                          that actually matters for signups
    src/pages/auth/LoginPage.tsx         /onboarding  -> /start
    src/App.tsx (SmartHomePage)          /onboarding  -> /start

  The long form is untouched and still reachable at /onboarding, linked from
  the first express screen. Re-entry is non-destructive: /start pre-fills the
  business name and persona from the existing profile, so a tenant part-way
  through the long form who lands here does not lose anything.
