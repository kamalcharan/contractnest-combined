────────────────────────────────────────────────────────────
WHY — root cause of "Service Cycle missing" and "Group Session gone"
────────────────────────────────────────────────────────────
ServiceBlocksStep.tsx hard-codes, for FlyBy lines:
  priced={!rfqMode && (fb.flyByType === 'service' || fb.flyByType === 'spare')}
So in rfqMode, `priced` was ALWAYS false — which killed Visits/Unlimited/
Billing Cycle/Service Cycle together with the price field (they were wrongly
bundled under one flag). Separately, the ENTIRE catalog-blocks section
(which is the only place Group Session lives) is wrapped in `{!rfqMode && (...)}`
— so it can never show in rfqMode, and Group Session was never one of the 4
FlyBy types to begin with. Neither of these are ChecklistRow bugs — they were
in ServiceBlocksStep's RFQ wiring, which this batch stops using for RFQ.

────────────────────────────────────────────────────────────
WHAT CHANGED — ChecklistRow.tsx (new `mode?: 'contract'|'rfq'` prop)
────────────────────────────────────────────────────────────
EVERYTHING below is gated on `flyBy` (custom lines only) — catalog
(non-flyBy) rows are 100% untouched, byte-for-byte, in every mode. Default
mode is 'contract' — existing callers that don't pass `mode` are unaffected.

  • Visits / Unlimited — now shows for a flyBy Service/Spare line in BOTH
    modes (previously bundled under the same flag as price, so it silently
    disappeared whenever price was hidden).
  • Billing Cycle chips — same fix, shows in both modes.
  • Service Cycle — REDESIGNED for flyBy rows only (catalog rows keep the
    exact previous design, unchanged), to match catalog-studio's Delivery
    Settings "Service Cycles" section: RefreshCw icon, explicit "Does this
    repeat?" Yes/No toggle, then days input + optional weekday-anchor chips +
    a live "next occurrences" date preview (6 dates). Applies to BOTH
    contract-flyby and rfq-flyby — one design, not two.
  • Price amount — hidden ONLY when mode='rfq' (replaced with "Quote pending"
    header text + a "The vendor sets the price when they quote this request"
    note). Contract mode: unchanged, still shows the real price field.
  • Advanced disclosure (tax / billing-only) — hidden ONLY when mode='rfq'
    (nothing to configure pre-quote). Contract mode: unchanged.
  • Description — swapped the plain <input> for the real RichTextEditor
    component, for flyBy rows in BOTH modes. This also fixes a real display
    bug: descriptions are rendered as HTML elsewhere (dangerouslySetInnerHTML
    in BlockCardConfigurable), but the old flyBy input only ever captured
    plain text — so typed HTML showed as literal "<p>text</p>" on screen.
