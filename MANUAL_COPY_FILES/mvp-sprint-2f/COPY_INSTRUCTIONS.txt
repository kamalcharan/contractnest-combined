WHAT WAS WRONG
──────────────
  Sprint 2e gated the Catalog Studio nav behind "5+ contracts", on the
  reasoning that "before that the seeded catalog is enough". Reported the same
  day: the menu was gone and it blocks operations. Correct — the reasoning was
  wrong, and here is exactly how.

  /catalog-studio is the ONLY route to four things:

    /catalog-studio/blocks           the 83-499 catalog blocks that onboarding
                                     just built and counted at the tenant
    /catalog-studio/templates-list   the ONLY place templates are managed
    /catalog-studio/configure        catalog configuration
    /catalog-studio/equipment        VaNi seeding

  Grepped for another way in: nothing else in the app links to templates-list.

  So the gate caused two things:

  1. A tenant finished onboarding, was told "83 service blocks built" by
     VaniIntelligenceStep and VaniWorkingStep, and then could not find them.

  2. Template seeding is parked pending "review patterns after usage". Usage
     requires access. With the nav hidden, no tenant could reach template
     management, so no tenant could produce a pattern — the gate quietly
     guaranteed the thing it was waiting for would never happen.

  The original justification only holds if the seeded catalog is fine as-is
  and the studio is for power editing later. With seeding parked, hand-building
  a template in that page IS the path.


WHAT CHANGED
────────────

  `wired: false`, `show: () => true` and the full reasoning above, so it is a

  The schedule was written before the code and the data were read. Two rules
