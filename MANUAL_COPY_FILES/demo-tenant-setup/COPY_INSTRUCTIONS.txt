- KT blocks were cloned from tenant "sharma elevators" (ae85acfe-…)
  because that tenant's blocks were produced by the real Sprint-1
  seeder (ktCatBlockMapperService → cat-blocks/bulk) — identical
  output to running onboarding, without needing the HMAC'd API path.

  decision) — their catalog blocks are authored service blocks with
  realistic INR prices (SAC 998531 / 998533, GST 18%).
- Billing events were generated CALENDAR-ALIGNED (start + N months),
  deliberately avoiding the known day-count drift bug in the
  derivation engine (see CLAUDE.md "Billing cadence dates drift").
- Every 3rd active contract's most recent past billing event is
  'overdue' (receivables realism); other past cycles are 'paid' with
  amount_settled = amount; past service visits are 'completed'.
- Draft/sent contracts carry no events (matches real behavior —
  events derive on activation).
- Fixed UUID scheme for cleanup & cross-referencing:
    a0…N auth users, b0…N user profiles, c0…N tenants, d0…N links,
    ee/ef/ea/eb/ec…  contacts, f<seller>…<nn> contracts.

POST-SETUP FIX (2026-08-02) — 09_fix_profile_type_perspective.sql
───────────────────────────────────────────────────────────────────
Symptom: buyer tenants (Pulse/Complex/Gold) landed on the Revenue
side with no vendor contracts visible; switching sides prompted
onboarding/activation.
Root cause: the tenant-profile edge function serves API field
business_type_id from the legacy profile_type COLUMN (not the
business_type_id column), and TenantContext only calls
initializePerspective() when that field is truthy. Scripts 01/07
left profile_type NULL.
Fix: profile_type := persona for all 7 demo tenants (mirrors what
real onboarding POST writes). Applied live 2026-08-02. Users must
re-login (or wait out the 30s edge profile cache) to see it.
