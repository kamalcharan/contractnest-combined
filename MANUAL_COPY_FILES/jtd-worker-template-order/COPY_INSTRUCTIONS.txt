BATCH: jtd-worker-template-order
================================
Fixes WhatsApp template parameter ORDER and restores whitespace cleaning.

Submodules affected: contractnest-edge  (1 file)
  contractnest-edge/supabase/functions/jtd-worker/handlers/whatsapp.ts

WHY
  Deployed jtd-worker is v35. It has NO generic path: for any template without
  a hand-written branch it does Object.values(templateData) — over a jsonb
  column, whose key order Postgres does not preserve. Every newly registered
  WhatsApp template therefore sends its {{1}}..{{N}} scrambled. MSG91 accepts
  the request and returns a request_id, the row reads status='sent', and the
  customer gets a mangled message. Verified against the real rows.

  cleanParam() — which collapses whitespace so MSG91 does not reject a body
  value containing a line break — was added in v34 and has since been LOST
  from both the deployed function and repo main. Three live BBB contacts have
  embedded CRLFs in their names; unfixed, every message to them fails.

WHAT CHANGED
  repo main already carries the generic path (reads templateVariableOrder,
  i.e. n_jtd_templates.variables, and emits body_1..N in declared order).
  This batch takes that file and adds back cleanParam(), applied centrally at
  all 4 points where a value enters `components` (named, positional, CTA
  button, header image) so no branch can bypass it.

STEP 1 — copy
  Copy-Item "MANUAL_COPY_FILES\jtd-worker-template-order\contractnest-edge\*" -Destination "contractnest-edge\" -Recurse -Force

STEP 2 — deploy the edge function
  supabase functions deploy jtd-worker
  (deployed version must go above 35; confirm in the Supabase dashboard)

STEP 3 — wire the 4 WhatsApp template ids
  Run wire_whatsapp_template_ids.sql (in this folder).
  It is deliberately NOT applied yet — see the header comment in that file.
