─── ROOT CAUSES FIXED ───────────────────────────────

A. TAG FILTER (and more): contactController.listContacts silently dropped
   `tags`, `user_status`, `show_duplicates`, `sort_by` and `sort_order`
   from req.query — the edge list route supported ALL of them all along.
   Chip counts came from /stats (which forwards tags) so they looked right
   while the list ignored every chip click. Sorting was equally a no-op.

B. GUEST DUPLICATION: NOT the contacts UI (both create paths already run
   checkDuplicates). gs_checkin_guest's reuse-lookup required an EXACT
   string phone match (stored '+919059951359' vs typed '9059951359') AND
   an existing Guest tag — so every repeat guest visit inserted a fresh
   contact. Proof: the Tejaswinni pair (8 Aug + 5 Sep), identical
   phone+email, created_by NULL at ~07:35 IST on meeting Saturdays.
   Migration 076 (LIVE): last-10-digits normalized match, no Guest-tag
   prerequisite, oldest match wins, stale 10-arg overload dropped.
   Verified: bare '9059951359' now resolves to the 8 Aug original.
