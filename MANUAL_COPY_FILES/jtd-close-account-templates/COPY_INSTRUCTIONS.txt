WHY THE `AND tenant_id IS NOT NULL`
  It is belt-and-braces, not load-bearing: with a NULL argument
  `tenant_id = NULL` already matches nothing, and Batch 1 (025) refuses a NULL
  call outright. It is written explicitly because n_jtd_templates is the ONLY
  table in this function holding SHARED rows — the global registry lives here
  as tenant_id IS NULL — and every step is wrapped in
  `EXCEPTION WHEN OTHERS THEN NULL`. If anyone later rewrites the predicate
  with COALESCE or IS NOT DISTINCT FROM, it would wipe the registry for every
  tenant SILENTLY. The clause makes that mistake hard to make by accident.
