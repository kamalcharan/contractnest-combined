─── WHAT IT DOES ───────────────────────────────────
 /ops/timeboard (menu: Timeboard, revenue side; expense shows a one-line note)
 Views: WEEK (a column per day, Mon–Sun) · DAY (a column per person, then
   Unassigned, then VaNi) · AGENDA (the phone default; a list per day).
   Earlier / Today / Later, a date picker, lane (All · Services ·
   Collections), Who (whole team / mine / unassigned), a Person select
   (when the team has more than one), search. Day and search live in the
   URL (?day=&q=) so a link lands on the same view.
 Columns: header = day (or person) + the hours that apply ("09:00–18:00",
   "day off", "Ganesh Chaturthi", "10:00–16:00 · dentist"); a top strip of
   everything WITHOUT a real time (unslotted services as draggable chips,
   payments / reminders / follow-ups / declared rolled up into chips that
   open a list); then the hours, hatched outside the working window, on a
   day off, a holiday or leave; a red rule at now on today.
 Blocks: services with a slot (proposed = dashed amber, asked = solid amber,
   confirmed = green, in progress = brand, overdue = red), sized by
   duration_minutes (024), side by side when they overlap, ⚠ when the
   reader says they clash. Day view: a person's follow-ups at their due
   time; the VaNi column carries the ladder's reminders at their time
   (greyed with "Open VaNi" when VaNi is off — the counterfactual is the pitch).
 THE GESTURE: pick a service up (chip or block) and drop it on a time — in
   the Day view on a person too. Never silent: a confirm bar reads "Move AC
   servicing · CN-1010 (Acme) to Tue 22 Sep, 2 pm and assign to Ravi", shows
   the clash preview computed from the availability the page already holds
   (day off · leave · outside 09:00–18:00 · overlaps …), and offers
   [Propose to customer] (jtd_schedule_visit, not confirmed) · [Confirm slot]
   / [Keep confirmed] (confirmed) · Cancel. A drop on another person's
   column assigns first (jtd_assign_visit) then schedules. The server's own
   warnings still come back in the toast. Nothing else is draggable:
   payments and reminders have no slot; a follow-up's reschedule has no API
   route yet (jtd_item_reschedule exists in the DB — pending).
 SIDE PANEL: tap any block, chip or agenda row → the full JobCard with every
   verb (nudge, call, assign, pause, confirm declaration, invoice, assign /
   schedule / confirm slot / start / mark done / ask customer, History) —
   the same wiring as Ops and the Plan tab — plus, for a service, FIND A
   SLOT: the next free times (14 days, working hours, skipping days off,
   leave, holidays and other timed services; for its technician, or for
   everyone when unassigned). Picking one opens the same confirm bar.
 STRIP over the grid: N need you · N clashes · N to place · N awaiting
   customer · N unassigned · N carried over → (list) · N parked → (list) ·
   VaNi is on/off. Day view adds the VaNi line: "Plan this day · N" when on
   (usePlanDay, 023), the greyed "VaNi would place N and send R reminders"
   when off.

 Verified: UI tsc 1170 = pristine on the assembled local state (expense-board
 + items-on-jtd + plan-view + availability + menu-flatten + this); vite
 build passes; the three views rendered in a throwaway harness with mocked
 rows and availability (week, day-by-person, agenda) — strips share one
 height so the hours line up across columns, hatching for a person's
 10:00–16:00, a Sunday off, a holiday and a morning's leave, overlapping
 blocks side by side, the follow-up in its person's column, the reminder in
 VaNi's. Not exercised against the live API in this session (no auth from
 here): the drag → confirm → schedule chain calls the same hooks the Plan
 tab's Schedule panel already uses.
