COPY INSTRUCTIONS — feature/group-session-jtd-notifications (Sprint 1 / Phase 1)
═══════════════════════════════════════════════════

Scope: Foundation work for the 5 Group Session WhatsApp notification triggers
(attendance ack, no-show regret, looking-forward, payment thank-you, absentee
reminder). No triggers actually fire yet — this sprint only lays the ground:
catalog-studio schema, a real admin auth fix, and the tenant-template
mapping tool.

Submodules affected: contractnest-ui, contractnest-api, contractnest-edge

───────────────────────────────────────────────────
FILES IN THIS FOLDER (mirror the exact repo paths)
───────────────────────────────────────────────────

contractnest-ui/
  src/App.tsx
    - Registers new route: /admin/jtd/templates -> TemplateMappingPage

  src/components/catalog-studio/BlockWizard/steps/service/DeliveryStep.tsx
    - New "Session timing" card (Group Session blocks only): start time +
      duration in minutes. Catalog-level only, not per-contract.

  src/utils/catalog-studio/catBlockAdapter.ts
    - Wires sessionStartTime/sessionDurationMinutes to/from
      config.groupSession.timing (read side, buildConfig write side, and the
      meta partial-update path used by the block editor panel).

  src/pages/admin/jtd/TemplateMappingPage.tsx  (NEW FILE)
    - New admin page: maps (tenant, source_type, channel) to an approved
      MSG91 template. Mandatory tenant_id on every row — no "open" system
      template can be created through this UI.

  src/pages/admin/jtd/hooks/useJtdAdmin.ts
    - New hooks: useJtdTemplates, useJtdTemplateOptions, useJtdTemplateMutations

  src/pages/admin/jtd/types/jtdAdmin.types.ts
    - New types: JtdTemplateRecord, JtdTemplateOptions, Create/UpdateTemplatePayload

  src/services/serviceURLs.ts
    - New ADMIN.JTD.TEMPLATES* endpoint constants

contractnest-api/
  src/middleware/auth.ts
    - New requireAdmin middleware (checks req.user.is_admin, populated by
      the existing authenticate middleware from t_user_profiles.is_admin)

  src/routes/adminJtdRoutes.ts
    - THE FIX: router.use(authenticate) + router.use(requireAdmin) now gate
      every /api/admin/jtd/* route. Previously this router had NO auth
      middleware at all.
    - New routes: GET/POST /templates, GET /templates/options,
      PATCH /templates/:id

  src/services/adminJtdService.ts
    - Removed the hardcoded 'x-is-admin': 'true' header (no longer needed
      or trusted — see edge function change below)
    - New methods: listTemplates, getTemplateOptions, createTemplate, updateTemplate

  src/types/adminJtd.dto.ts
    - New template-mapping DTOs

  src/validators/adminJtdValidators.ts
    - New validators: listTemplatesValidation, createTemplateValidation,
      updateTemplateValidation

contractnest-edge/
  supabase/functions/admin-jtd-management/index.ts
    - THE OTHER HALF OF THE FIX: replaced the client-suppliable x-is-admin
      header check with a real server-side check — verifies the caller's
      JWT via supabase.auth.getUser(), then checks t_user_profiles.is_admin
      for that user. This function no longer trusts anything the caller
      claims about their own admin status.
    - New routes: GET /templates, GET /template-options, POST /templates,
      PATCH /templates (id via query param)
    - Added PATCH to CORS allowed methods

  supabase/functions/cat-blocks/index.ts
    - New validateGroupSessionTiming() — validates
      config.groupSession.timing.startTime (HH:mm) and .durationMinutes
      (positive integer) on both create and update. Previously `config` was
      accepted completely unvalidated.

  supabase/migrations/jtd-framework/008_seed_group_session_source_types.sql  (NEW FILE)
    - Seeds 5 new n_jtd_source_types: group_session_attendance_ack,
      group_session_noshow_regret, group_session_looking_forward,
      group_session_payment_thankyou, group_session_absentee_reminder
    - Deliberately does NOT seed any tenant_id=NULL system template for
      these — see the comment in the file for why (mandatory-tenant model,
      doubles as a natural per-tenant rollout gate).
