The checked-out copy of serviceURLs.ts is BEHIND the deployed build. It was
missing OCC_ASSIGN and OCC_ASSIGN_DEFAULT even though
useGroupSessionsDashboard.ts calls both — the repo copy did not compile
against its own hook. Same repo-drift pattern as the jtd-worker last week.

I added those two keys back (matching the live routes) as well as DUES, so the
file in this batch is now self-consistent. But if YOUR local copy has other
newer keys I cannot see, a whole-file overwrite would delete them.

SAFEST PATH — add three entries by hand instead of copying the file.
In src/services/serviceURLs.ts, inside API_ENDPOINTS.GROUP_SESSIONS, next to
ROSTER, paste:

    OCC_ASSIGN: (id: string) => `/api/group-sessions/occurrence/${id}/assign`,
    OCC_ASSIGN_DEFAULT: (blockId: string) => `/api/group-sessions/occurrences/${blockId}/assign-default`,
    DUES: (blockId: string, fyStart?: string | null) =>
      `/api/group-sessions/dues/${blockId}${fyStart ? `?fy=${fyStart}` : ''}`,

(If OCC_ASSIGN / OCC_ASSIGN_DEFAULT are already there, add only DUES.)

The other five source files are safe to copy whole — they are additive.
