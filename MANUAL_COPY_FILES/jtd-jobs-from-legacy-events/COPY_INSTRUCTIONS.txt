─── OWNER ACTION (the notice sends only after this) ─
 MSG91's email API refuses a send without a template id (worker
 handlers/email.ts), and no "contract accepted" template exists in MSG91 —
 the existing pair (contract_signoff_notification / contract_signoff) is
 the acceptance REQUEST to the buyer, a different message. Register an
 MSG91 email template with variables
   seller_name, buyer_name, contract_title, contract_number,
   contract_value, accepted_on, contract_link
 (the HTML is in the n_jtd_templates row to copy from), then:
   UPDATE n_jtd_templates SET provider_template_id = '<msg91 template id>'
   WHERE template_key = 'contract_accepted_email' AND tenant_id IS NULL;
 From then on every public acceptance emails the seller. A WhatsApp
 variant needs its own MSG91 WhatsApp template (positional, per the
 CLAUDE.md trap) and a second template row on channel 'whatsapp'; the
 helper is email-only today.

 Not changed (noted): update_contract_status V1 still queues bare
 messages for contract_sent / contract_accepted / contract_expired /
 rfq_sent — harmless (the worker drops them with the same log line) but
 noisy; those are the seller's own status changes, no notice is owed.
