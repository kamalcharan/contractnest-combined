WHAT THIS IS
───────────────────────────────────────────────────────────────────
The point of the whole redesign. Until now the storage meter read 0
for everyone because nothing wrote contract evidence through the
broker. Service execution still used the legacy per-tenant storage API
and stored a durable public URL.

Now: file → evidence broker (slot → PUT → confirm) →
create_service_evidence carrying the registry id. The file lives under
contracts/**, is METERED against the tenant's 40 MB quota, and is read
back through a short-TTL signed URL instead of a durable public one.

SUBMODULES AFFECTED: contractnest-ui, contractnest-edge
DATABASE: migration evidence-storage/008 ALREADY APPLIED LIVE
          2026-09-22. Source-of-record copy only — it DROPs a
          function, so a second run fails.

⚠️ AN EDGE FUNCTION MUST BE REDEPLOYED
───────────────────────────────────────────────────────────────────
contractnest-edge/supabase/functions/service-execution/index.ts now
forwards p_evidence_id. Until you deploy it, uploads still work but
the registry link is never stored, so the file is orphaned from its
service record (and the sweeper will eventually reclaim it as an
unconfirmed orphan). Deploy AFTER copying:

    supabase functions deploy service-execution

WHY THIS TURNED OUT SMALL
───────────────────────────────────────────────────────────────────
Measured before writing anything:

    t_service_evidence        0 rows
    t_contract_attachments    0 rows

No service evidence has EVER been captured in production. So this is a
clean swap of an unused write path — no data migration, no URLs to
preserve, no dual-read period. The EventAssetProgress UI wired to a
non-existent endpoint is likewise unused rather than broken in flight.

WHAT MIGRATION 008 DID
───────────────────────────────────────────────────────────────────
  t_service_evidence.evidence_id     -> t_contract_evidence(id)
       The service row is still the SERVICE record (ticket, event,
       block, proof kind); only the FILE moved. file_url is kept and
       nullable so the five readers keep their shape.

  create_service_evidence            gains p_evidence_id, and the
       21-arg original is DROPPED rather than left beside it. A stale
       overload has caught this codebase three times
       (gs_checkin_guest, check_contact_duplicates,
       jtd_escalate_payment_call) and that is not happening a fourth.

  3 readers now emit evidence_id     get_service_ticket_detail,
       get_service_evidence_list, get_service_ticket_report

FILES (contractnest-ui) — 2
───────────────────────────────────────────────────────────────────
  src/components/contracts/TicketEvidencePanel.tsx
      Upload goes through useUploadEvidence (compress → slot → PUT →
      confirm). The slot request is the GATE, so a refusal happens
      before any bytes move, and 'quota_exceeded' / 'mime_not_allowed'
      are surfaced as something the user can act on rather than a
      generic failure.
      ALSO NEW: a "Captured Evidence" list. The panel was previously
      upload-only — there was no way to see what had been attached.
      Each chip mints its own signed URL on click.

  src/hooks/queries/useServiceExecution.ts
      CreateEvidencePayload gains evidence_id and label.
