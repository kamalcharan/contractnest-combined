INDUSTRY FIX (2026-10-02) — crane got "Healthcare" instead of Facility Management
----------------------------------------------------------------
Cause: "What do you service?" derives your served industries from the
templates you pick (the template's PRIMARY industry). The resources edge
function reads v_resource_templates_by_industry, which has one row per
template × linked industry, then de-duplicated by keeping the FIRST row —
so for a template linked to several industries (e.g. a lift linked to both
facility_management and healthcare) whichever row came first won, and the
"primary" flag on it could be a non-primary link. The UI also stopped at
8 pages, so some picks never resolved at all.

contractnest-edge/supabase/functions/resources/index.ts
  · stable tie-break ordering (id, linked_industry_id) after the score orders
  · de-duplication keeps the is_primary row when a template appears twice
  DEPLOYED LIVE as resources v64 (v63 was == repo HEAD before deploy; v64
  verified == this file). Copying it only brings the repo in line.

contractnest-ui/src/lite/onboarding/useGlobalTemplates.ts
  · MAX_PAGES 8 → 20 so the whole catalogue (610 templates) resolves
  (covered by the vani-onboarding-cleanup ui Copy-Item line)

FIX (2026-10-03) — First contract: "No contacts yet" + "status code 409"
----------------------------------------------------------------
Owner, new tenant valuenotes: the rehearsal showed no clients and failed
with 409, although the tenant has 3 sample clients in Test.
Cause: this batch's earlier api.ts change let a request's OWN x-environment
header win over the stored environment (added for the T&C copy). But
useContacts sends x-environment from AuthContext state, which still says
Live after onboarding flips storage to Test — so the contact list read Live
(no clients), and the composer got header Live vs body Test → CONTEXT_CHANGED
(409). Before this batch the interceptor always forced the stored
environment, which First contract relies on.
Fix:
  src/services/api.ts — stored environment always wins again; the only
    exception is the axios OPTION envOverride: 'live' | 'test' (a config
    option, not a header, so it never leaves the browser / no CORS change).
  src/pages/onboarding/steps/TermsConditionsStep.tsx — the T&C copy to the
    other environment passes envOverride instead of an x-environment header.
Verified: axios 1.11 keeps the option into the interceptor (stray "live"
header → "test"; envOverride "live" → "live"); UI tsc 1154 with all three
batches (no new errors); vite build passes.
TEST: [ ] new tenant → First contract lists the sample clients, services
          load, contract assembles
      [ ] finish Terms → Catalog Studio shows the T&C in BOTH Live and Test
