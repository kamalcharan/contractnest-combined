WHAT THIS FIXES
─────────────────────────────────────────────────
Two issues found testing the vendor quote page live (mvp-rfq-24):

1. "Cycles are not showing in RFQ" — the vendor never saw how often a
   visit repeats. Traced this to rfq_resolve_for_vendor's block SELECT:
   it only ever returned quantity + billing_cycle. billing_cycle
   (prepaid/postpaid/monthly/...) is a BUYER PAYMENT TERMS concept — it
   describes when the buyer pays, which means nothing before a vendor is
   even chosen — and the vendor UI's CYCLE_LABEL map didn't even have
   entries for prepaid/postpaid, so it printed the raw enum string
   ("prepaid") verbatim. The thing a vendor actually needs — how often the
   visit repeats — lives in custom_fields.config.serviceCycleDays and was
   never selected by the RPC at all. Verified live against PRJ-1005: after
   the fix, "Door System Inspection & Adjustment" correctly shows
   service_cycle_days: 30, "Safety Devices Inspection" shows 180, spares
   correctly show null (no cadence).

2. Formatting issue (the pasted stock-analysis HTML) — traced to the exact
   same live RFQ: a "Text Block" line (position 5) had that content as its
   block_description, stored as real HTML from the buyer's RichTextEditor
   (<p><span style="color: rgb(...)">...</span></p>). Two places rendered
   this as a bare JSX text node instead of real HTML, so the tags showed
   literally: VendorQuotePage.tsx's per-line description, AND ChecklistRow
   .tsx's own collapsed summary row (so the buyer would see this on their
   own card too, not just the vendor). Fixed both using SafeHtml.tsx — an
   existing sanitized-HTML-render component already used elsewhere in the
   codebase, not a new pattern.

Explicitly NOT done (per the third discussion point, still open): did not
change the vendor's quote UI to go through the Contract Wizard/FlyBy flow.
That's a bigger tradeoff (dependency-light public page vs. richer
structured quotes) that hasn't been decided yet — see conversation.

Also NOT attempted: a full sweep of every {description}-shaped render in
the codebase. Only fixed the two spots proven (via the live PRJ-1005 data)
to actually carry RichTextEditor HTML and render it raw. If the same
symptom shows up elsewhere, it's the same fix (swap for SafeHtml) but
each spot should be confirmed first, not blanket-changed.
